# I Can Run A Show repository assets

Fifteen original PNG files were downloaded byte-for-byte from the public `taylordrew4u2/Showrunner-ICanRunAShow` repository at pinned revision `2989ec0dfb5439d888276bf1bceba7d53fc76995` into `assets/showrunner/`. Each file was visually inspected and its PNG dimensions, byte count, and SHA-256 digest recorded. No image was generated, cropped, resized, recolored, or reconstructed. Original source colors, text, proportions, and full-resolution pixels remain intact.

## Source and capture context

The [pinned README](https://github.com/taylordrew4u2/Showrunner-ICanRunAShow/blob/2989ec0dfb5439d888276bf1bceba7d53fc76995/README.md) separates seven App Store promotional graphics in `docs/promo/` from application captures in `docs/screenshots/`. The [pinned capture guide](https://github.com/taylordrew4u2/Showrunner-ICanRunAShow/blob/2989ec0dfb5439d888276bf1bceba7d53fc76995/docs/screenshots/CAPTURE.md) states that the committed screenshots were generated against a local production build with the in-memory mock API, using sample show data, no real account, and no database. Show dates are relative to the capture day. This asset update downloaded the existing captures; it did not run the application, access a production account, or regenerate screenshots.

The landscape banner and six phone-framed promotional images use `sourceKind: "repository-product-artwork"` and are explicitly captioned **Repository product artwork**. The eight application images use `sourceKind: "repository-app-capture"`, pinned source links, and **Repository app capture** captions. The production-build context describes how the repository images were made and is not a claim that they were captured from the current live deployment.

The mobile show-detail and show-page visuals depict a private producer workspace. They are not the public audience viewer; the capture guide explicitly says there is no viewer-link shot. Stage-remote settings display a learned `Enter` key in the capture fixture. These images and their clicker illustrations do not establish physical Bluetooth pairing or venue hardware validation. Sample contract statuses do not establish a real performer signature. No physical remote interaction, venue show, production account, real signature, subscription purchase, or fresh runtime test was performed while adding these assets.

## Gallery order

The banner is the product-overview cover and first gallery view. Six app-capture views follow: Workspace & cues (desktop workspace paired with mobile soundboard), Show planning, Contracts & cues (agreement status paired with schedule), Mobile workspace, Performer directory, and Stage remote. Six portrait promotional views follow those captures: Every show, Run the show, Run of show, Show page, Rolodex overview, and Stage remote overview. This provides **13 gallery views and 15 image references**, preserving both original companion pairs.

The mobile `run-show.png` is 860 × 2090; it shows the performer soundboard and fade controls. Its caption does not invent a visible cue countdown. Other phone interface captures are 860 × 1864; desktop interface captures are 2560 × 1800. Promotional images are 1920 × 1080 for the banner and 1320 × 2868 for the six portraits.
