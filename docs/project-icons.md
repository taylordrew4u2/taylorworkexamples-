# Project identities and icon evidence — October 12, 2026

The portfolio contains 16 current public projects. **15 use authentic project logos, app icons, or favicons** acquired from their public repositories or canonical website. The micro-short website uses neutral **MS** text initials because no verified project logo or favicon was found.

[`identities.js`](../identities.js) defines a plain-language `purpose`, three `workflows`, and a `previewContext` for each project. It also records the icon path, intrinsic dimensions, source URL, kind, and preservation notes. These identities merge into the project catalog. Icons appear beside project names in selected work, the full archive, and project dialogs. Archive entries explain what each project does, list its workflows, and offer direct live-site or App Store links when those destinations are available.

These explanations describe implemented or source-supported workflows. A workflow label does not establish that the displayed capture exercised every feature. Context labels preserve distinctions such as sample shows, fictional screenplays, native development captures, pending permissions, virtual microphones, and source-derived overviews. Existing case and image disclosures remain applicable.

## Color and display policy

Project icons preserve their original colors and proportions. No icon was generated, repainted, recolored, cropped, or reconstructed for this portfolio. Native PNG resizing is the proportional reduction described above. Page styling and 4u Digital branding remain black, white, and gray; authentic project icon colors remain visible, as do genuine project screenshot colors. Do not apply a monochrome filter to these assets.

Icons identify a project and are separate from screenshot evidence. Their presence does not imply a live deployment, App Store listing, client relationship, or additional runtime validation. Public-source status still comes from [`repository-state.js`](../repository-state.js), and screenshot provenance remains in [the image evidence record](image-evidence.md).

## Deployment and maintenance

[`vercel.json`](../vercel.json) configures an additional static Vercel mirror: `framework: null`, `npm ci` for installation, `npm run build` for the build, and `dist` as the output directory. GitHub Pages remains configured separately. The planned Vercel project belongs to the `taylordrew4u2s-projects` team and will be connected to this public repository after GitHub CI passes. This file records the configuration and intended destination; the actual Vercel URL and deployment result should be recorded after deployment.

When updating identities, preserve source links and intrinsic dimensions, use factual purpose/workflow language, and keep direct destination links consistent with the canonical project data. Copy only authentic identity assets into `assets/project-icons/`. The static build packages referenced assets and does not fetch GitHub state at runtime.

This documentation update records provenance and intended behavior. It adds no claim that new unit tests, browser checks, or deployment checks have passed.
